# T096 按鍵、螢幕、電量與 Station RF 顯示（2026-10-05）

> **日期式驗證紀錄。** 顯示偏移／供電修正仍有參考價值；本文舊 USER／低電 SystemOFF 行為自 10/9 起由 [RTC 待機](t096-rtc-standby-2026-10-09.md) 取代。現行操作／部署以 [交接入口](assistant-handoff.md) 為準。

使用者確認先信任原廠ADC換算，電錶校準後做；授權更新並燒錄LilyGO 584C、Heltec V4 ED2C、T096 F035。
0.6-dev／wire v5、B組923.8MHz不變，兩個Station仍接收同一Client；每boot僅第一個Station控制。

## 操作

| 操作 | 行為 |
| --- | --- |
| 開機／USER喚醒 | Ready，顯示5秒 |
| USER短按 | 亮屏5秒、重計時；不改追蹤／測試模式 |
| USER長按2秒 | 提示放開；放開才請求Storage，純電池送最後STATE後SystemOFF |
| USB供電時USER長按 | 回Ready、關GNSS、維持USB供電與診斷，顯示5秒 |
| RST | 硬體重啟，不做電源toggle |
| 未接USB且Ready 12小時 | 保留既有自動Storage |

喚醒時仍壓住USER只建立按鍵基準，放開後才接受下一個手勢，避免同次按壓立即再關。
深眠後Web無法喚醒。這裡「關機」是SystemOFF，不是切斷電池或充電器。

TFT使用ST7735 MINI160x80_PLUGIN／rotation1／原廠invert設定。160×16 RGB565行buffer為5120 bytes，
每次只送一行；背光5秒GPIO期限不等待RF，SLPOUT等待120ms時仍服務GNSS／radio。
Ready保持Vext但TFT SLPIN與背光off、GNSS switch關；Tracking熄屏不關共用Vext，SystemOFF才切Vext與FEM。
這個Ready耗電尚未量測，不等同SystemOFF或數月待機。

## 電量與低電量

- 依原廠3.0V internal reference、12bit、4.9倍divider；每秒在RF idle時開ADC_Ctrl，等待10ms，
  丟棄首次讀取，平均4次再關divider。原始ADC與換算mV保留USB log。
- 2.5–4.5V範圍以外回unknown（mV=0），不冒充0%或觸發關機；USB在時抑制低電量關機。
- <3.5V顯示警告；三次有效讀值<3.2V且無USB，關GNSS／停止新RF，LOW BATTERY顯示5秒後SystemOFF。
  開機取樣發生在radio／GNSS之前；運行中亦檢查。低電量關機不額外發PA封包，Station可能只看見最後電量與之後失聯。
  警告期間接USB會取消關機並回Ready。
- 百分比與Station沿用3.2V=0%、4.15V=100%的線性估算，螢幕有`~`；尚未校準、不宣稱剩餘時間。
- STATE與TEL都帶電壓。Station用90秒內最新有效STATE或TEL顯示電量、產生提醒及cloud snapshot；
  只有STATE不偽造溫濕度TEL、精確衛星數或TEL接收年齡。T096溫濕度仍unknown。

## RF 顯示

兩種Station OLED不再用TEL覆蓋訊號。只觀察已接受、綁定Client的DATA/TEL/DIAG/GNSS/STATE/probe；
格式／綁定／DATA序號拒收不刷新訊號cache。Good：SNR≥7dB且RSSI≥−105dBm；其餘SNR≥0為OK、<0為Bad；
90秒沒有效RF為Miss。重綁清cache，新boot STATE直接建立新RF證據。
GPS行、DATA FPS、位置freshness及追蹤gate保持原規則。
`/api/status.lora.signal/rssi/snr`與OLED一致；rolling平均仍只計DATA，packet event保留逐包原始RSSI/SNR。
資訊頁有效的0 dBm顯示數值，只有unknown／expired才顯示`--`。
Cloud的既有RSSI/SNR欄位仍為DATA量測，沒有擅自改其schema定義。

### T096 USB分享後的實機修正／驗證

USB serial核對為`C3BFA5F76F915E4A`，application PID 8071、DFU PID 0071；application-only DFU成功，保留bootloader與SoftDevice。
首次DFU後雖回到application USB，但沒有USB log／新STATE。當時Station顯示的是舊封包，age持續增加，不能當成新韌體成功收包。
查明Adafruit SPITFT只替variant宣告的SPI／SPI1等呼叫`begin()`；自建SPIM2必須在`initR()`前由韌體啟用。
補上`displaySpi.begin()`後重新DFU成功；主機回歸也加入此外部函式庫初始化契約，原本僅fake TFT的測試漏掉了這項相依行為。

- 新boot USB identity與Station STATE一致；Ready每30秒持續回報，避免只看一張舊snapshot。
- ADC實機raw約1153–1160，換算4138–4163mV；USB供電，仍未用電錶校準。STATE與TEL都已收到有效電量。
- 新T096由V4控制短RF測試，收到70 probes、counter missing 0、最大間隔1014ms，boot期間未改變。
- Web開始追蹤與停止命令均收到確認；Tracking時兩筆TEL帶電量4145mV，溫濕度仍unknown；最後回Ready、command 3 confirmed。
- GNSS rail啟用後實際UART能回覆PDTINFO／CFGNAV／CFGMSG。這次室內短測有效RMC／GGA／epoch計數率仍0、DATA 0，
  未證明有效定位或GNSS 2Hz；不能將設定回讀等同真實位置輸出率。熄屏後是否正常定位仍需室外驗收。
- 實體USER短按與面板亮／熄目視尚待使用者回報；低電量與純電池SystemOFF電流仍屬主機邏輯驗證／待量測。

### 2026-10-06 T096 TFT列錯位修正

使用者回報文字斜著錯位。T096仍是ST7735、橫向160×80；LilyGO是SH1106、128×64。
目前使用的Adafruit 1.11.0 `INITR_MINI160x80_PLUGIN`設定column/row offset為26/1，
Heltec同名panel preset則為24/0。加入`include/t096_display.h`板型wrapper，
在initR後、rotation前套用24/0；保留rotation 1、invert、SPIM2、row canvas與5秒熄屏行為。
這是面板address window的修正，未改RF、GNSS、電量或Station控制。

`tools/test_t096_display.py`擷取已安裝的實際Adafruit初始化／rotation／address-window函式，
重現舊設定每列x=1..160，並驗證修正後五列均x=0..159、全螢幕y=24..103。
原本只檢查canvas尺寸／文字邊界的測試不能涵蓋面板隱藏offset。
主機display／power／GNSS startup／position／radio lifecycle測試與build通過，
application 121412 bytes、DFU zip 122215 bytes。
核對USB serial `C3BFA5F76F915E4A`後，F035 application-only DFU完成；package只有application，
保留bootloader／SoftDevice。新USB boot `393A2960`與Station STATE boot `960112992`一致，
Station回報Ready，USB持續回報ADC／電量，USB供電時約4.14V。
使用者於修正燒錄後目視確認「文字正常，不再斜著錯位」。此次實機驗收支持面板offset修正，
不延伸為無線充電電流、電池容量、滿電或室外GNSS定位的驗證。

DFU zip SHA-256：`5f643a0eb29fd87c0ba835720cbb00ca20b96b543fb6d0222e84c2b297582a43`。
