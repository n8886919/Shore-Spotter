# LilyGO Station 接收 T096（2026-10-04）

本輪接著的 Station 是 LilyGO T-Beam Supreme `584C`，Client 是 T096 `F035`。
兩端採 B 組923.8 MHz／SF10／BW125／CR4/5／wire v5，韌體0.6-dev。
Station 固定網址為 `http://shore-48ca4357584c.local/`。

本機 device manifest 保留 V4、LilyGO 與同一個 T096 的 profile。以
`SHORE_DEVICE=station-lilygo-584c pio run -e tbeam-station` 選 LilyGO。
原 NVS 綁定 `E91C` 已用既有 `/api/whitelist` 明確改為 `F035`，不只改首次開機預設值。
T096 每次開機只接受第一台 Station 控制；接收可共用，切換控制者需重啟 Client。
本次先讀到 T096 尚無控制者；實機 test／stop 已確認 LilyGO 取得控制權，無需重啟 Client。

## 原設定與 Axiom

- 原板有效 `axiom_log/config` 已依 namespace、Written entry、blob index/chunks與CRC取回。
  ingest key與metadata保存在本機私人目錄、權限0600，不提交key／NVS／原始app到Git。
- 原設定為enabled、US、dataset `shore-spotter`；app-only更新保留NVS，沒有以query token取代ingest key。
- 原app、NVS、partition table、OTA metadata都有私人備份。stub讀取在固定位置中斷，
  ROM讀取完整app成功，與兩段獨立讀取內容一致；更新亦用ROM寫入並驗證hash。
- 原100 KiB TLS前門檻另加32 KiB batch，LilyGO約117 KB閒置heap無法達到。
  80／48 KiB版本只成功首批，之後因最大區塊36,852 bytes而停住。
  80／32 KiB版本能持續上傳，但並行實測最低heap只有5,496 bytes，故不交付此做法。
- 最終做法啟用 Supreme QSPI PSRAM，僅將32 KiB upload batch優先配置於PSRAM；
  無可用PSRAM時保留內部fallback。保留原100 KiB總量／48 KiB連續區塊的TLS門檻、
  48 KiB採樣門檻、queue與buffer容量；未改SD流程或RF參數。
  `/api/axiom`新增free／largest heap、門檻、PSRAM容量與batch位置，可核對配置與low_memory原因。

設定依據：[LilyGO Supreme原廠PSRAM設定](https://github.com/Xinyuan-LilyGO/LilyGo-LoRa-Series/blob/master/docs/en/t_beam_supreme/t_beam_supreme_hw.md)、
[Espressif heap capabilities API](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/system/mem_alloc.html)。
