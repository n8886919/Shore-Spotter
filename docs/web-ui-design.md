# 網頁設計規格

## 2026-11-13 Android 原生拍攝介面

- App 以海邊使用為優先：滿版相機、錄影／同檔暫停繼續、縮放；主畫面單一「Station 控制／Station 斷線」入口，控制與資訊整合在同一個可捲動浮層，提醒疊在影像。點按面板外相機預覽可收合，不重新綁定相機或改變錄影。
- 控制／資訊改原生 UI 直接走既有 API；不嵌原網頁、不搬入地圖／雷達、重複標頭／重整、封包測試、SD 或診斷內容。
  原網頁繼續供 debug，本項不重排原網頁或改追蹤後端規則。
- 手機電量／充電狀態與儲存「剩餘 XX.X GB」整合在右下畫質右側的兩行資源區；上行接電時顯示綠色閃電 icon＋N%，拔電時顯示「電量 N%」，接電且滿電也保留閃電與百分比；下行顯示剩餘 GB。13sp 文字共用一個半透明背景，沒有白框。
  最新閃電 icon／百分比改動尚未部署到手機，待下次接續部署與驗證。
  未連線入口顯示「Station 斷線」，點按只開 IP 設定；取得新鮮 Station 狀態後才可開面板，失聯即停用並收起浮層。
  資訊保留兩端電量、定位、校正、轉動速度與 IP。
  Surfer 是無 SD 的 Heltec T096；Station SD 只供 debug，不在 App 呈現。
- 錄影不收音，解析度／FPS 可選；錄影中不可改畫質。手機固定 Station 旁，以原生精確位置走既有位置 API。
- 海邊狀態用不透明背景：綠色 `#7acd9c` 就緒／已選模式、沙色等待／提醒、粉紅 `#e99a94` 未確認／斷線／錯誤、灰底停用；紅綠依最新指示提高飽和度。
  依目前 source 重算文字對比：NEUTRAL 11.24:1、GOOD 6.71:1、WARNING 8.40:1、DANGER 5.24:1、DISABLED 5.42:1；保留文字／勾選，不只改字色。面板不透出相機畫面。
  定位未確認固定粉紅底，尚未取得第一筆定位仍為沙色等待；錄影狀態文字為粉紅底，暫停狀態文字為沙色底。
- 上方元件視覺底板 32dp／觸控列 48dp；橫向間距 8dp、面板按鈕垂直間距 12dp，沒有整條頂列背景。
  頂列只留定位／Station，固定寬 112／128dp，沒有儲存 chip；文字變動不推動位置。
- 一般按鈕與底板維持小圓角長方形，`FieldStyle` 圓角 6dp；錄影鍵例外為半透明圓形底板／中心紅圓，錄影中改停止方塊，沒有白色外框。
- 錄影／暫停／倍率／右下畫質／資源區均高 48dp、距底部 26dp 對齊。倍率／暫停／畫質／資源區底板 alpha `0xb3`（約 70%）；錄影底板 `0x99`（60%）、中心紅色 `0xb3`。
  畫質固定寬 128dp、距右 172dp；資源區固定寬 144dp、距右 20dp，位於畫質右側。只有倍率／畫質加不透明白色細框；Station 面板開啟時倍率／畫質／資源區一起收起，面板收合後恢復。半透明底板對比隨影像改變，不套用實心元件的固定值。
- 移除 1×／2×／5× 快捷鍵，保留倍率數字與滑桿；軌道 8dp、拖曳點 28dp、觸控列 48dp。滑桿列為前次寬度的 80%，左側預留錄影／暫停區，再以 `max(200dp, 螢幕寬 - 464dp)` 夾限寬度。
- 手機定位於前景持續更新，移除停止／開始更新按鈕；定位視窗只顯示狀態，離開前景仍停止取樣。
- App 主畫面與對話框吞掉手機內建音量鍵，不調音量或觸發錄影；外接裝置另外辨識，尚未加入遙控錄影。
- IP 欄不顯示或要求協定，使用數字鍵盤並允許 IPv4 的多個點，鍵盤完成即連線；換家中 Wi-Fi／手機熱點時依 Station 螢幕更改並保存。
- App／硬體命令期限與測試界線見 [Android 紀錄](android-app-2026-11-13.md)。

## 2026-11-13 HTTP 逾時與前景恢復（已部署 584C）

- HTTP 仍序列處理到完整本文讀取結束；2 秒期限到達即結束本次等待並釋放佇列，
  不依賴瀏覽器的 abort 是否及時完成。逾時後等 1 秒才允許下一筆請求，避免持續失聯時密集重試。
  遲到的 fetch／本文成功或失敗均不能更新資料、控制世代或干擾後續請求。
- 切到背景／pagehide 時取消未完成 HTTP 與未送出的拖曳目標；回到前景、快取頁恢復或網路重新上線時，
  清除舊資料的新鮮度，立即重讀 Station／Client／GPS／RF 狀態，不等背景輪詢的下一週期。
  同一次恢復的事件合併處理；收到成功新資料前維持未知燈號，不以恢復事件冒充連線成功。
- 保留既有 HTTPS 手機定位輔助頁流程：輔助頁在前景時，背景 Station opener 仍可提交剛收到的有效新位置。
  重新同步會丟棄舊的待送位置，不重放既有 POST；origin／popup 身分與位置驗證不變。
- Servo、Client 控制及其他 POST 不自動重送。已送出而逾時／中斷代表結果未確認，提示查看最新狀態；
  舊操作意圖在重新同步後失效，保留原有 boot／epoch／seq／stamp 與 2 秒控制期限。
  不改變實際追蹤模式、角度或 Client 位置回報狀態，也不改版面。
- 保留最近 16 筆頁面 RAM 錯誤 `httpFailures`（時間、方法、無 query 的路徑、截短原因），
  可用瀏覽器 console 檢查；不保存 body／位置，不自動上傳，重新載入即清除。

重現、回歸與實機界線見 [修復紀錄](web-recovery-2026-11-13.md)。

## 2026-10-28 RSSI／SNR 分開分級（2026-11-13 已部署 584C）

- Surfer「連線與裝置診斷」的合併數字列改為兩列：「RSSI 訊號強度」「SNR 訊號品質」，各顯示 Good／OK／Bad／Off。
  Good 綠、OK 黃褐、Bad 紅、Off 灰，保留文字，不只依賴顏色。原始 dBm／dB 放在同位置下方「RF 原始數值」折疊內。
- RSSI：≥ −105 dBm 為 Good、≥ −115 且 < −105 為 OK、< −115 為 Bad。
  SNR：≥ 7 dB 為 Good、≥ 0 且 < 7 為 OK、< 0 為 Bad。
  沿用既有 Good RSSI 與 Good／OK SNR 門檻，新增 RSSI 下方 10 dB 的 OK 區間。
  這是顯示用分級，非晶片解調極限／實測餘裕，不改後端綜合 signal、告警或 RF 參數。
- 來源仍為最近接受的綁定 Client RF 樣本，與 GPS DATA／FPS 分開；有效 0 仍分級。
  API 明確 null（尚無或超過既有 90 秒 RF freshness）為 Off，文字明示不代表 Client 關機。
  缺欄位／非法值為 `--`；HTTP 失敗立即清除分級與原始值，超過 6 秒未成功更新也清除，避免保留過期 Good。
  6 秒為網頁 status 3 秒輪詢的資料期限，不改後端 90 秒 RF 判定。恢復成功輪詢後重新顯示。
- Good 不代表 GPS 定位、雙向控制或無漏包；不更動其他控制、版面順序與 LoRa 燈。

- 原 Surfer Info 的配對 ID 改為藍色、有底線的可點按鈕。點擊才開啟編輯框，顯示目前 ID，

- 選擇只暫存；啟動後收到匹配 Client／boot／Station／命令的新頻率 LoRa STATE，才保存。
  未驗證顯示「待驗證」，不以 BLE 回覆或 HTTP 202 冒充成功。命令 pending 時禁止重複送出。
- 保留其餘版面、GPS／Servo 操作、診斷折疊與既有無線連線測試；不恢復已移除資訊。

## 2026-10-11 現行控制與介面

正式原始碼已整合 Youmi 35 kg（5–8.4 V、359°）＋串口控制板，固定 **M0**。
Station UART2 **9600 8N1、TX GPIO43、RX 不配置**；`#00P0500!`～`#00P2500!`，無換行。
`include/servo_controller.h` 合併最新目標、去重、最多 50 Hz 非阻塞送出；控制板自行產生 50 Hz PWM。
角度 0～359°，中位 **179.5°／1500 μs**；開機輸出中位、預設手動。沒有 ACK 或實際角度回授。
UART 寫入成功只證明 Station 交給 UART，不能證明控制板接受或 Servo 到位。
只留手動／GPS；舊 115200 SET／SET2／SYNC 外部輸入不再編入正常 Station，`mode=uart/jetson` 回 400。
GPS α UI、預測運算與設定 API 已移除；`/api/track/prediction` 回 404，舊 NVS 鍵不讀寫。
GPS 仍使用兩端有效且新鮮的位置、磁偏角與校正，失效轉完最後有效目標；不自動切換來源。
共用速限預設 30°/s、整數 1～90，NVS `servospd` 保存；GPS 目標每 50 ms 重算。

資訊頁四區：**定位資訊／Station Info／控制板／Surfer Info**。
座標只顯示 Google Maps 連結；手填欄位由上至下經度／緯度／誤差。
卫星顯示無／少／中／多；HDOP 下方說明其為幾何指標，不能換算成已知實際誤差。
手機回報半徑、Station 30 秒 RMS 散布、實際誤差分開；真實誤差需對照已知參考位置。
Station 顯示自有溫濕度與 SD 記錄狀態，無運行時間／Servo 來源／SD 錯誤計數；
Surfer 顯示電池、GPS 開啟／關閉、STATE／DATA 年齡與 RF 品質，無 USB 供電列。
GPS 狀態只依近期 STATE；未知或過期不假裝為關閉。
控制板區顯示 M0、串口、命令角度／脈寬／字串與 UART 計數，實際角度為未知。
磁偏角移到定位資訊；速度點數字開視窗、儲存成功才關閉，指南針整數 0～359、預設 90。
「鏡頭置中」回 179.5°；停穩後填北 0°、東 90°、南 180°、西 270°重新校正（只存 RAM）。
手動完整圓軌道 0～359°，0／359 在下、90 左、180 上、270 右，放開才送、端點不環繞。
UI 刻度延續鏡頭方向反向映射 `ui=359-raw`；控制板區顯示 raw 角度；地理方位另依校正計算。
手機定位權限流程延後、不加複製診斷摘要。

部署目標：LilyGO 584C，B 組 923.8 MHz／SF9、wire v5；已 application OTA 更新，HTML 比對、M0 輸出與持續 STATE 通過；見 [部署驗證](servo-ui-deployment-2026-10-11.md)。
主機通過 140 項 native、實際 HTTP／UART／GPS gate／NVS、圓形操作及地圖回歸。
實體 M0 接線、UART 接受、轉向、端點、帶載及戶外 GPS 精度仍待驗收。

## 雷達與地圖

- **零個、一個或兩個有效 GPS 都可選雷達**。定位消失不得強制切成地圖。
- 兩端有定位時雷達以 Station 為中心；只有 Station 時以 Station 為中心，只有 Client 時以 Client 為中心。
  無定位時保留格線與角度控制，不畫虛構的位置／相對距離。
- 地圖只用即時有效點決定中心：單端用該點，雙端用兩點中點。歷史軌跡不拉動地圖中心。
- 雷達以上方對應**校正偏移**旋轉；偏移 90° 時 E 在上、N 在左。位置、方向字、地理波束使用同一旋轉。
- 路徑只保留最近 5 分鐘；不新增期間文字、路徑圖例或其他已移除說明。
- 支援 pinch／wheel 縮放。地圖圖磚由瀏覽器取得；沒有圖磚仍可呈現位置、軌跡及比例尺。

## 上半圓角度控制

- 軌道與雷達最外圈同半徑，**永遠固定在畫面上半圓**：左 0°、正上方 90°、右 180°。
  地圖也採相同控制排列，不隨校正偏移或磁偏角旋轉。
- 手動模式顯示粗軌道、刻度及 **44 px 圓形把手**，把手內顯示角度並保留小握把線條。
- GPS／UART 模式**只隱藏軌道、刻度與握把線條，仍保留圓形角度標記**。
  標記顯示目前 `servo.angle` 換算的 UI 角度，不能拖曳，不因不可操作而把數字淡到難以辨識。
- 手動顯示待達目標，拖動時顯示本地預覽。**拖動不送出，放開才送出**。
  保留鍵盤方向鍵及既有 HTTP 排程、新鮮度檢查與模式隔離。
- pointercancel、失去 capture、第二觸點、切模式／視圖／頁面、尺寸變化都取消未完成手勢。
- UI 與內部角度維持 `raw = 180 - ui`。控制刻度不是地理方位；波束仍用
  `mount_offset + declination - raw` 計算。角度資料是命令值，不是實體 Servo 回授。
- 開機手動、Servo 90°，校正偏移預設 90° 並視為有效。**雷達可選不等於 GPS 追蹤可選**：
  GPS 模式維持雙端有效定位等後端條件；資訊頁重新校正仍要求 Servo 回到 90° 且停穩。

## GPS／LoRa 紅綠燈

三個燈為**同一垂直群組**，由上而下固定：**Station GPS、Client GPS、LoRa**。
每項都有顯眼圓形燈、名稱與短狀態字，不只靠顏色傳達狀態。
LoRa 的狀態行顯示 `1.8 FPS · 10s` 形式的最近 10 秒平均；連線狀態保留於燈色、提示及可存取名稱。

| 燈號 | 綠 | 紅 |
|---|---|---|
| Station GPS | `/api/track.station.fix` 有效 | 無有效定位 |
| Client GPS | `/api/track.client.fix` 有效 | 無有效定位 |
| LoRa | `/api/track.rf_alive` 為真：90 秒內接受過綁定 Client 的 DATA／TEL／DIAG／GNSS／STATE／RF probe 任一有效封包 | 不符合 RF 活動條件 |

- LoRa 綠燈不表示 GPS 有效，也不表示 RF 沒有丟包。GPS 綠燈不表示預期精度一定合格。
- RF 仍活躍但 `linked=false` 時，提示、可存取名稱與資訊頁連線文字顯示「收到遙測，等待 DATA」。
  `linked`／`data_fresh` 保留 5 秒 DATA 門檻，GPS 追蹤另用原有更短的新鮮度 gate；不以遙測延長定位有效期。
  舊 API 缺少 `rf_alive` 時才回退到 `linked`，不把欄位缺漏假造成 RF 成功。
- FPS 由 Station 的接受 DATA 到達時間計算：最近 10,000 ms 包數 ÷ 10；不把網頁輪詢、TEL／DIAG 或拒收包當作 FPS。
  開機前 10 秒分母仍為 10。停止收包後逐筆退出窗口、自然歸零；RF 連線燈與 10 秒 DATA FPS 窗口分開。
  API 欄位為 `lora_fps_10s`；沒有此欄位顯示 `-- FPS`，資料過期時顯示灰燈及「資料過期」。
- 尚無 track 或最後一次成功取得 track 超過 **3 秒**：三燈灰色，顯示「等待資料」或「資料過期」。
  不得長期保留過期綠燈，也不得把瀏覽器失聯直接說成 GPS／LoRa 故障。
- 雷達模式依畫面長寬動態選擇位置及圓心，優先最大化圓圈，同時避開燈號群組與把手。
  直向通常放上方空白，橫向通常放左側空白；接近方形時可移動圓心。
  燈號到外圈保留把手所需間距，不得只按固定直／橫向 CSS 放置而遮住圈。
- 地圖模式固定靠左，上下位置隨畫面高度調整；不能跟著地圖資料漂移。
